# University Research Opportunity Portal

Thia contains a Node.js REST API,MySQL database and a HTML/CSS/JavaScript frontend styled with Bootstrap.

## Features
Create,list,view,update and delete research opportunities all CRUD operations are done.
It contains unique ID,title,description,research area,faculty member,department,required skills,available positions,application deadline and Open and Closed status.
Change status between Open and Closed directly from the opportunity display.
Bootstrap frontend with search,status filter,counts,detail view,form validation,success and error messages and delete confirmation.
Appropriate HTTP status codes in Postman: 200,201,400,404 and 500.
Postman collection is included in postman/Research_Opportunity_Portal.postman_collection.json.

## Requirements
Install these before running the application:
1. Node.js and npm.
2. MySQL Server or XAMPP with MySQL/MariaDB enabled.
3. Postman for API testing.
I did step 1 in VScode terminal.
I did step 2 in XAMPP.

## Setup and run
### 1.Create the database
Start MySQL in xampp. In a terminal (I used VScode terminal), from the project directory, import the schema:

```bash
mysql -u root -p < database/schema.sql
```
than enter the password

If your local MySQL root account has no password, use:

```bash
mysql -u root < database/schema.sql
```

Alternatively open `database/schema.sql` in MySQL Workbench or phpMyAdmin and execute it. The script creates the `research_portal` database and `opportunities` table. It does not insert sample data create records using the application or API.

### 2.Configure environment variables
Copy `.env.example` to `.env` in the project root:

macOS/Linux:
```bash
cp .env.example .env
```

Windows Command Prompt:
```bat
copy .env.example .env
```

Open `.env` and set your MySQL host,port,username,password, and database. Example for a local MySQL installation with an empty root password:

```env
PORT=3000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=research_portal
```
Do not commit `.env` to GitHub. It is ignored by `.gitignore`.

### 3.Install Node.js dependencies
In the project root:

```bash
npm install
```

### 4.Start the application
```bash
npm start
```

When the database connection is successful the terminal displays the local URL. Open:

Frontend: http://localhost:3000
API list endpoint: http://localhost:3000/api/opportunities

Keep the terminal running while using the site. The frontend is served by the same Express server so no separate frontend server is needed.

### 5.Use the portal
Click `Add opportunity` fill in the required fields and save.
Click `View details` to retrieve the selected record through `GET /api/opportunities/:id`.
Click `Edit` to update a record.
Click `Close opportunity` or `Reopen` to update the status.
Click `Delete` to remove a record after confirmation.
Use search and status filters to narrow the displayed records.

The list and details are fetched from the API. No opportunity records are hard-coded in the frontend.

## REST API reference
Base URL: `http://localhost:3000/api/opportunities`

| Method| Endpoint| Purpose| Success status|
| POST | `/api/opportunities` | Create an opportunity | `201 Created` |
| GET | `/api/opportunities` | Retrieve all opportunities | `200 OK` |
| GET | `/api/opportunities/:id` | Retrieve one opportunity | `200 OK` |
| PUT | `/api/opportunities/:id` | Update one or more fields | `200 OK` |
| DELETE | `/api/opportunities/:id` | Delete an opportunity | `200 OK` |

Validation errors return `400 Bad Request` missing records return `404 Not Found` unexpected server/database failures return `500 Internal Server Error`.

### Example JSON body
```json
{
  "title": "AI for Accessible Learning",
  "description": "Explore machine-learning methods that help personalize digital learning resources.",
  "research_area": "Artificial Intelligence",
  "faculty_name": "Dr. Sara Ahmed",
  "department": "Computer Science",
  "required_skills": "Python, basic machine learning, data analysis",
  "positions": 2,
  "application_deadline": "2026-12-15",
  "status": "Open"
}
```

For a partial update with `PUT`send only the fields to change. For example:
```json
{
  "status": "Closed"
}
```
The ID is generated by MySQL and must not be supplied in the request body.

## Postman testing checklist
Import `postman/Research_Opportunity_Portal.postman_collection.json` into Postman. It includes requests for:

1. Create opportunity 1.
2. Create opportunity 2.
3. Create opportunity 3.
4. Retrieve all opportunities.
5. Retrieve one opportunity by the ID saved from the first create request.
6. Update an opportunity.
7. Change its status to Closed.
8. Delete the opportunity.
9. Request the deleted opportunity to verify a `404`.
10. Send invalid data to verify a `400`.

The collection stores the created ID in a collection variable automatically. Run requests in order or manually set `opportunityId` to an existing ID.

## Troubleshooting
`Database connection error:` Confirm MySQL is running and `.env` credentials are correct.
`Unknown database:` Run `database/schema.sql`.
`Port 3000 is already in use:` Change `PORT` in `.env`, then open the corresponding localhost port.
`Table missing:` Re-run the schema file.
`Frontend cannot load records:` Check that `npm start` is running and that the terminal has no database errors.
`Date format error:` Use `YYYY-MM-DD` for the deadline.
`Invalid/missing field:` Complete all required fields and ensure positions is a whole number greater than zero.
